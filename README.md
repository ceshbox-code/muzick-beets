# muzick-beets

Наведение порядка в музыкальной коллекции на Synology NAS: [beets](https://beets.io) в Docker + веб-панель управления с прогрессом.

Результат: из перепутанной коллекции получается библиотека вида

```
Исполнитель/Альбом/NN - Название.mp3
```

Исходные файлы **не изменяются** (монтируются только для чтения), упорядоченная копия собирается в отдельной папке.

## Что внутри

| Файл | Назначение |
|---|---|
| `install.sh` | установка одной командой: каталоги, конфиг, контейнеры |
| `muzick.sh` | управление: импорт, перетегирование, статистика, обновление |
| `panel.py` | веб-панель (прогресс, кнопки импорта, блок MusicBrainz) |
| `fix_tags.py` | исправление кракозябр в тегах и объединение вариантов написания исполнителей |
| `config.yaml` | конфиг beets (шаблон путей, плагины) |

## Требования

- Synology DSM 7 с Container Manager (Docker)
- SSH-доступ (Панель управления → Терминал и SNMP) и пользователь с правами sudo
- mp3-файлы (для других форматов подойдёт тот же конфиг)
- по желанию: VPN-контейнер на NAS, если MusicBrainz недоступен из вашей сети

## Установка одной командой

Репозиторий: https://github.com/ceshbox-code/muzick-beets

```bash
curl -fsSL https://github.com/ceshbox-code/muzick-beets/archive/refs/heads/main.tar.gz | tar xz \
  && sudo bash muzick-beets-main/install.sh
```

Без GitHub: скопируйте папку на NAS (SMB/scp) и выполните `sudo bash install.sh` внутри неё.

Параметры по умолчанию можно переопределить переменными окружения:

```bash
sudo SRC_DIR=/volume1/music LIB_DIR=/volume1/music_clean \
     VPN_CONTAINER=VPN PANEL_PORT=8338 TZ_NAME=Europe/Berlin \
     bash muzick-beets-main/install.sh
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SRC_DIR` | `/volume1/music` | исходная коллекция (только чтение) |
| `LIB_DIR` | `/volume1/music_clean` | чистая библиотека |
| `BASE_DIR` | `/volume1/docker/beets` | конфиг, база, панель |
| `VPN_CONTAINER` | `VPN` | имя VPN-контейнера; пустое значение отключает VPN |
| `PANEL_PORT` / `WEB_PORT` | `8338` / `8337` | порты панели и просмотра beets |
| `PANEL_PASS` | генерируется | пароль панели (логин любой) |
| `FORCE_CONFIG` | `0` | `1` = перезаписать `config.yaml` (старый сохранится в `.bak`) |

Установку можно запускать повторно: существующий конфиг и пароль сохраняются.

> Папку `LIB_DIR` лучше заранее создать в DSM как общую папку (Панель управления → Общая папка), иначе она не будет видна в File Station и Audio Station.

## Использование

```bash
sudo /volume1/docker/beets/muzick.sh help
```

Типичный порядок работы:

1. `muzick.sh tags` — разложить всё по существующим тегам (быстро, без интернета).
2. `muzick.sh fix-encoding` — отчёт о «кракозябрах» (кириллица в Windows-1251, прочитанная как Latin-1, например `Àëèñà` вместо `Алиса`). Если замены выглядят правильно: `muzick.sh fix-encoding --apply`, затем `muzick.sh organize`.
3. `muzick.sh artists-suggest` — найти варианты написания одного исполнителя (`inxs`/`INXS`, `Сукачёв`/`Сукачев`). Черновик `artist-aliases.suggested.tsv` в `BASE_DIR/config` проверьте и сохраните как `artist-aliases.tsv`; формат: `вариант<TAB>каноническое имя`. Затем `muzick.sh artists-preview`, `muzick.sh artists-apply` и снова `muzick.sh organize`. Разные формы записи одного человека (`В.С. Высоцкий`, `Владимир Высоцкий`) скрипт сам не склеивает: добавьте их в файл вручную.
4. `muzick.sh mb-test Accept` — пробное перетегирование одного исполнителя через MusicBrainz, с вопросами. Делать лучше **после** исправления кодировок: с кракозябрами в тегах MusicBrainz альбомы не находит.
5. `muzick.sh mb-all` — перетегирование всей библиотеки в фоне; прогресс в блоке «Перетегирование через MusicBrainz» веб-панели.
6. `muzick.sh dups` — поиск дубликатов, затем ручная доработка пропущенного.

Все команды, меняющие теги, сначала делают копию базы (`musiclibrary.db.bak-ДАТА` в `BASE_DIR/config`). Теги в файлах переписываются в ID3v2.3. Перед `--apply` и `organize` в панели не должно быть запущенных задач.

Веб-панель: `http://IP_NAS:8338`. Кнопки импорта в панели работают в обычной сети NAS (не через VPN), поэтому MusicBrainz-проходы запускайте через `muzick.sh`.

## Как работает VPN-часть

Если указан `VPN_CONTAINER` и он запущен, команды, которым нужен MusicBrainz (`mb-test`, `mb-all`, `beet`), запускаются в его сетевом окружении (`--network container:ИМЯ`). Сам VPN-контейнер и всё, что работает через него, при этом не затрагивается. Контейнер должен быть клиентом, то есть исходящий трафик должен идти в туннель; установщик покажет, отвечает ли MusicBrainz напрямую и через VPN.

## Безопасность

- Панель использует HTTP и пароль Basic-авторизации: держите её только в локальной сети, наружу не пробрасывайте.
- Пароль хранится в `BASE_DIR/muzick.env` (права 600) и передаётся контейнеру панели через переменную окружения, поэтому виден в `docker inspect`.
- В панели нет операций удаления. Исходная папка монтируется только для чтения.

## Обновление и удаление

```bash
sudo /volume1/docker/beets/muzick.sh update   # новый образ + пересоздание контейнеров
sudo /volume1/docker/beets/muzick.sh down     # удалить контейнеры (данные остаются)
```

## Известные ограничения

- Процент в блоке MusicBrainz приблизительный: считается по альбомам с MusicBrainz-ID и по строкам лога пропущенного.
- MusicBrainz ограничивает частоту запросов (около одного в секунду), поэтому проход по большой библиотеке занимает часы.
- Неофициальные сборки и самодельные альбомы в MusicBrainz обычно не находятся: для них остаются теги из файлов.
