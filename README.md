# muzick-beets

Управление музыкальной коллекцией с помощью [beets](https://beets.io/) на Synology DSM. Проект предоставляет веб-панель и CLI для импорта музыки, обработки тегов и диагностики возможных дубликатов. Поддерживаются два сценария: импорт в отдельную библиотеку и работа непосредственно с файлами в выбранной папке **без копирования**.

## Как устроено хранение

- `SRC_DIR` — папка с исходной коллекцией. В обычном режиме она подключается в контейнер только для чтения как `/downloads`.
- `LIB_DIR` — целевая папка библиотеки, куда beets импортирует файлы в режиме копирования.
- `WORK_DIR` — корневая папка, в которой разрешена прямая работа с файлами. Она подключается в контейнер как `/work` с правом записи.
- `BASE_DIR/config` — база данных beets, настройки, журналы и состояние веб-панели.

По умолчанию `WORK_DIR` равен `SRC_DIR`, но можно указать другой каталог. Для прямой работы используется отдельная база `musiclibrary-direct.db`, чтобы не смешивать её с основной библиотекой.

**Важно:** режим без копирования не означает режим «только чтение». Если операция обновляет теги, они могут быть записаны непосредственно в музыкальные файлы. Перед массовой обработкой сделайте резервную копию.

## Установка

Требуются Synology DSM с Docker или Container Manager, доступ к терминалу и права на чтение/запись в выбранные каталоги.

Скачайте репозиторий, перейдите в его каталог и запустите установщик, указав свои пути:

```sh
sudo SRC_DIR=/volume1/music \
  LIB_DIR=/volume1/music_clean \
  WORK_DIR=/volume1/music \
  BASE_DIR=/volume1/docker/beets \
  bash install.sh
```

Замените пути примера на реальные пути вашей системы. Установщик сохраняет параметры из существующего файла `muzick.env`; переменные, явно переданные при запуске, имеют приоритет. Файл с настройками и паролем панели должен иметь права доступа `600`.

Установщик не должен менять владельца всей музыкальной коллекции рекурсивно. Проверьте, что UID/GID, под которыми работают контейнеры, имеют необходимые права на выбранные каталоги.

## Основные команды

После установки команды доступны через скрипт `muzick.sh` в каталоге проекта:

```sh
sudo /volume1/docker/beets/muzick.sh status
sudo /volume1/docker/beets/muzick.sh help
sudo /volume1/docker/beets/muzick.sh logs
sudo /volume1/docker/beets/muzick.sh dups
```

Примеры команд для обработки папки в режиме без копирования:

```sh
sudo /volume1/docker/beets/muzick.sh direct-tags "Исполнитель/Альбом"
sudo /volume1/docker/beets/muzick.sh direct-mb "Исполнитель/Альбом"
```

Укажите фактический путь к `muzick.sh` и имя папки относительно `WORK_DIR`.

## Работа без копирования файлов

В веб-панели выберите режим работы в указанной папке и укажите нужный каталог внутри корня `WORK_DIR`.

В этом режиме:

- файлы не копируются в `LIB_DIR`;
- файлы не перемещаются в структуру каталогов beets;
- используется отдельная база `musiclibrary-direct.db`;
- команда `direct-tags` обрабатывает существующие теги без автоматического сопоставления с MusicBrainz;
- команда `direct-mb` выполняет сопоставление с MusicBrainz;
- при записи метаданных изменения могут попасть непосредственно в исходные музыкальные файлы.

Панель может работать только с каталогами внутри смонтированного `WORK_DIR). Если нужная папка находится вне него, измените `WORK_DIR` при настройке контейнеров. У пользователя контейнера должны быть права, необходимые для выбранной операции.

Сначала проверьте работу на небольшой тестовой папке и убедитесь, что резервная копия доступна.

## Веб-панель и безопасность

Веб-панель помогает выбирать папки, запускать операции, смотреть состояние задач и журналы, а также контролировать состояние базы и предупреждения о неполных метаданных.

Панель использует Basic Auth. **Не публикуйте её напрямую в Интернет:** Basic Auth без HTTPS не защищает пароль от перехвата. Для удалённого доступа настройте HTTPS через обратный прокси и дополнительно ограничьте доступ. Проверьте правила межсетевого экрана и не открывайте порт панели наружу без защиты.

## Параллельные операции

Команды CLI и веб-панель используют общий блокировочный файл `config/.muzick.lock`, чтобы не допускать одновременной записи в базу через поддерживаемые сценарии запуска. Не запускайте `beet` вручную внутри контейнера в обход `lockrun.py`: такой запуск может не учитывать общую блокировку.

## Проверка дубликатов

Команда `dups-audit` проверяет базу SQLite в режиме только для чтения и формирует отчёт о подозрительных совпадениях по путям, MusicBrainz ID и тегам. Она не меняет базу и не удаляет музыкальные файлы.

```sh
sudo /volume1/docker/beets/muzick.sh dups-audit
sudo /volume1/docker/beets/muzick.sh beet duplicates -a -p
sudo /volume1/docker/beets/muzick.sh beet duplicates -p
```

Совпадение исполнителя, названия композиции или альбома само по себе не доказывает, что аудиофайлы идентичны: одна композиция может встречаться на сборниках и разных изданиях альбома. Проверяйте отчёт вручную и не удаляйте файлы автоматически без дополнительной проверки.

## Резервное копирование и ограничения

Перед массовым импортом или изменением тегов:

1. Сделайте резервную копию базы beets и важных музыкальных файлов.
2. Проверьте свободное место в целевой папке `LIB_DIR).
3. Проверьте пути `SRC_DIR`, `LIB_DIR` и `WORK_DIR), а также права доступа.
4. Начните с небольшой тестовой папки и просмотрите журнал выполнения.
5. Не удаляйте предполагаемые дубликаты до проверки результата.

Образ контейнера может использовать тег `latest`; обновляйте его осознанно и перед обновлением сохраняйте базу и настройки.

В текущем репозитории отсутствует вспомогательный файл `fix_tags.py`. Поэтому расширенные команды `fix-encoding` и `artists-*` не будут работать, пока этот скрипт не будет восстановлен. Это не блокирует базовую установку и основные сценарии работы.
